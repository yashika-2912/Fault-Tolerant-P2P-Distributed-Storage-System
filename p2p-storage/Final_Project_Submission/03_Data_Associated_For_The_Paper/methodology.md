# Methodology

Three project processes (Flask coordinator and N1–N3) were started in an isolated project copy on localhost. Ports 5000, 6001–6003 and 6100 were confirmed free. `P2P_DB_PATH` directed SQLite to isolated run databases; node chunks stayed in clone-local storage. Verified configuration: 1 MiB chunk size, replication factor 2, heartbeat interval 1 s, timeout 4 s.

For transfer performance, the harness generated one `os.urandom(size)` payload in memory per size and reused it for three sequential POST/GET trials. Sizes were 100 KiB, 1 MiB, 5 MiB and 10 MiB. `time.perf_counter()` surrounded each HTTP call. A trial passed only if HTTP succeeded and retrieved bytes equaled the payload. Throughput uses decimal Mbps, `bytes × 8 / seconds / 1,000,000`; it is application-level effective throughput. Means, medians, sample standard deviations and trial counts are in `analysis/benchmark_summary.csv`; chart error bars are sample deviations.

Replication was checked by comparing every SQLite replica mapping with the corresponding file on disk and hashing its encrypted bytes against the recorded chunk SHA-256. All 51 chunks in 12 performance files had two valid copies on N1/N2. Failure testing uploaded 16 KiB, terminated only the harness-owned N1 process, then polled `/status` every 100 ms. Detection is termination request to observed N1 DOWN; promotion interval is first observed DOWN to first observed N3 ACTIVE; total recovery is termination to observed N3 ACTIVE. After each test, SQLite rows and both N2/N3 chunk files/hashes were checked and the harness verified downloaded bytes. Three trials passed.

The integrity test uploaded 4,096 random bytes, flipped one byte in the isolated N1 PRIMARY encrypted chunk, confirmed its hash differed from metadata, then downloaded and compared with original in-memory bytes. Retrieval passed using the alternate replica. Corrupt data remained on N1, so this establishes detection and fallback, not repair. Audit-chain verification was true after download. Raw outputs are preserved under `raw_results/`; normalized measurements and summaries are generated by `analysis/collect_results.py` and `analysis/analyze_results.py`. The 11 previously reported unit tests were not rerun.
